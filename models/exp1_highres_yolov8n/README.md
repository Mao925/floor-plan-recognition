# Exp 1: 高解像度学習 (imgsz=1024)

## 仮説
入力解像度を 640 → 1024 に上げれば、shower などの小物体の検出漏れが減り、特に shower の mAP@0.5 が改善する。

## 設定
- Model: YOLOv8n
- imgsz: 1024 (ベースラインの 640 → 変更)
- epochs: 50
- batch: 8 (メモリ制約のため 16 → 縮小)
- seed: 42
- 学習環境: Google Colab T4 GPU

## 結果(test セット)

| 指標 | Baseline | Exp 1 | 改善 |
|---|---|---|---|
| mAP@0.5 | 0.815 | **0.903** | **+0.088** |
| mAP@0.5:0.95 | 0.616 | ~0.65 | +0.03 |

### クラス別 mAP@0.5

| クラス | Baseline | Exp 1 | Diff |
|---|---|---|---|
| door | 0.986 | 0.987 | +0.001 |
| shower | 0.417 | **0.730** | **+0.312** |
| sink | 0.823 | **0.962** | **+0.139** |
| staircase | 0.704 | 0.759 | +0.055 |
| toilet | 0.966 | 0.985 | +0.020 |
| window | 0.992 | 0.993 | +0.000 |

## 解釈

- **仮説完全に支持**: shower が 0.42 → 0.73 と 75% 向上
- 想定外の発見:sink も大幅改善(0.82 → 0.96)
- door / window は既に上限近く(>0.99)で変化なし → モデルが妥当に動いている証拠
- 一般則:**「すでに高精度のクラスは恩恵を受けず、低精度クラスほど解像度UPの恩恵が大きい」**

## 副作用

- 学習時間: ベースラインから増加
- batch を 16 → 8 に減らす必要(GPU メモリ制約)

## 次の仮説

- モデルを n → s に拡大することでさらに改善するか? (Exp 3 の候補)
